1. Stack rebuscado (por que, no “otra lib mas”)
-----------------------------------------------
FeedbackIQ gano con CTranslate2 int8 + LRU, no con un API de traduccion.
Aca el equivalente, cosas que el resto no pone:

  pymupdf4llm
    Mismo motor que PyMuPDF, sale Markdown con titulos/tablas.
    Companeros hacen fitz.get_text() y se come el layout.
    Si el markdown trae NIT + total + items y las reglas cierran:
    no se llama Gemini. Eso es el ahorro gordo.

  Pillow resize lado largo = 768
    Gemini: imagen <=384px en AMBOS lados = 258 tokens.
    Mas grande = tiles 768x768 x 258 tokens c/u.
    Renderizar la pagina 1 a PNG ~768px es el int8 de este proyecto.
    Nunca mandar el PDF nativo de 8 paginas.

  google-genai
    SDK oficial. response_schema = InvoiceDraft (Pydantic).
    Cero reintentos por JSON roto. Cookbook de Google es
    exactamente “PDF invoices + structured outputs”.

  count_tokens (API) + usage (respuesta)
    Analogia exacta de tokenizer.py de FIQ.
    tiktoken o200k_base NO sirve: vocabulario de OpenAI, no de Gemini.
    Antes: client.models.count_tokens(model, contents=[prompt, image])
    Despues: response.usage_metadata
      prompt_token_count / candidates_token_count
    Guardar los dos. Mostrar por peticion.

  Hash sha256 del archivo
    Misma factura = no se vuelve a pagar Gemini.
    Como el LRU de traduccion en FIQ.

  RapidOCR (ONNX)
    Fallback sin instalar PaddlePaddle (el infierno de deploy).
    CPU, liviano. Si la tabla sale vacia -> cola humana.
    No es el primer ojo. No se “verifica” con Gemini encima
    (eso duplica y no ahorra: la imagen se paga igual).

  nomic-embed-text (ya lo tenes en Ollama)
    RAG del asistente. No LangChain. sqlite + chunks.

  qwen3.5:0.8b
    El modelo mas chico que ya bajaste. Solo chat, nunca vision.

4. Pipeline
-----------
1. sha256 del bytes. Si existe en DB, devolver ese document (0 tokens).
2. Guardar data/originals/{id}
3. Clasificar:
     PDF y pymupdf4llm da texto util
       y extract_fields_heuristic encuentra las keys
       y validate cierra
         -> source=pymupdf, tokens_in=0, tokens_out=0
     si no (foto, scan, texto incompleto):
         render pagina 1 @ 768px (fitz + Pillow)
         tokenizer.estimate_image(w,h)
         tokenizer.count_gemini(prompt, png)   # ANTES
         gemini.extract(png) -> InvoiceDraft + report
         tokenizer.from_usage(response)        # DESPUES
         source=gemini
     GeminiUnavailable:
         RapidOCR -> draft + report de reglas
         source=rapidocr, tokens=0
4. validate.run  (siempre)
5. confidence.score
6. status: Gemini/RapidOCR -> needs_review
   digital + reglas ok + AUTO_APPROVE_DIGITAL -> approved
7. store: draft + usage + hash
8. job.done

Gemini no pisa totales. validate marca fault.

7. validate.py
--------------
- sum(items.net) ~= subtotal ±0.01
- subtotal - discount == taxable
- taxable * rate ~= tax
- subtotal + tax - discount == total
- fechas; due >= issued
- NIT CO + digito de verificacion (DIAN, modulo 11)
- unique (nit, number, total)
- no negativos indebidos

pytest = DoD minimo. Sin IA en este archivo.


8. RAG + chat
-------------
knowledge.txt = como usar CUADREIQ (cola, aprobar, inbox,
que significa “no cuadra”, como llega el mail).
Al boot o /api/rag/reindex:
  chunker -> embed nomic-embed-text -> tabla rag_chunks

POST /api/chat
  { message, document_id? }
  retrieve top_k chunks
  ollama /api/chat  modelo 0.8b
    system: sos el asistente de CUADREIQ. solo el manual +
            el documento si viene id. si piden enviar el pdf
            por correo, responde JSON:
            {"action":"email","document_id":"...","to":"..."}
            si falta to, pregunta el correo.
  return { text, action?, tokens_local? }

POST /api/chat/email
  { document_id, to }
  solo si document.status in (approved, needs_review)
  report_service -> n8n:
    { to, subject, filename, path, document_id }
  n8n: Gmail + attach file. No Gemini. No Ollama.

El modelo NO manda el correo. El backend si, via n8n.
